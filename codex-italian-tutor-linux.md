# Задача для OpenAI Codex: локальное веб-приложение «Итальянский с нуля»

## 1. Роль и общий режим работы

Ты — OpenAI Codex, работающий как senior full-stack developer, product engineer, UX/UI designer, DevOps-инженер и QA-инженер внутри текущего репозитория.

Создай полноценное современное веб-приложение **«Итальянский с нуля»** — интерактивного AI-репетитора итальянского языка для русскоязычных пользователей уровня A0–A1.

Целевая среда эксплуатации — **локальный Linux-ПК**. Развёртывание и настройка приложения на Linux являются обязательной частью задачи, а не отдельной рекомендацией на будущее.

- полноценно работать в демо-режиме без внешних API-ключей;

- отдельными компонентами;
- статическим макетом;
- набором фрагментов кода;
- незавершёнными заглушками;
- демонстрацией только главного экрана.

Ты должен самостоятельно:

1. Изучить текущий репозиторий.
2. Проверить существующие инструкции и пользовательские изменения.

Не задавай уточняющих вопросов, если можешь принять разумное инженерное решение самостоятельно.

Если часть возможностей зависит от аппаратуры, браузера, разрешений или внешнего API, реализуй рабочий fallback и честно укажи ограничение в интерфейсе и документации.

# 3. Целевая Linux-среда

По умолчанию ориентируйся на современный Linux-дистрибутив с systemd, например Ubuntu, Linux Mint или Debian.

Приложение должно поддерживать два способа локального запуска.

## 3.1. Основной способ: нативный запуск

Используй:

- актуальную LTS-версию Node.js;
- npm, если существующий проект не использует другой package manager;
- локальную файловую базу SQLite;
- production build frontend;
- Node.js-сервер, раздающий frontend и API;
- systemd для постоянного фонового запуска.

Нативный запуск должен быть основным и полностью документированным вариантом.

## 3.2. Дополнительный способ: Docker Compose

Подготовь Docker-вариант как дополнительную возможность:

- `Dockerfile`;
- `docker-compose.yml` или `compose.yml`;
- volume для постоянного хранения базы;
- healthcheck;
- restart policy;
- запуск без root внутри контейнера, если это практически возможно;
- `.dockerignore`.

Docker не должен быть единственным способом запуска.

## 3.3. Сетевой режим

По умолчанию приложение должно быть доступно только на локальном компьютере:

- `HOST=127.0.0.1`;
- порт задаётся через `PORT`;
- значение по умолчанию — `3000`.

Для доступа из локальной сети пользователь может явно установить:

```env
HOST=0.0.0.0
PORT=3000
```

Не открывай firewall автоматически.

В документации объясни:

- как узнать локальный IP;
- как открыть приложение с другого устройства;
- что доступ через `0.0.0.0` делает приложение видимым в локальной сети;
- как ограничить доступ;
- что для публикации в интернет потребуются отдельные меры безопасности.

## 6.1. Скрипт установки

`install.sh` должен:

1. Проверить Linux.
2. Проверить наличие Node.js и npm.
3. Проверить подходящую версию Node.js.
4. Не устанавливать системные пакеты без явного подтверждения.
5. Установить npm-зависимости.
6. Создать production build.
7. Создать локальную директорию данных.
8. Создать `.env` из примера, если его нет.
9. Выполнить миграции.
10. При необходимости заполнить демонстрационные данные.

12. Предложить установку systemd service как отдельный явный шаг.

Скрипт должен использовать безопасный shell-режим:

```bash

```

Не запускай весь проект от root.

## 6.2. systemd

Подготовь unit-файл:

```text
deploy/linux/italian-tutor.service
```

Требования:

- запуск от отдельного непривилегированного пользователя или текущего пользователя;
- корректный `WorkingDirectory`;
- `EnvironmentFile`;
- `ExecStart` с production-командой;
- `Restart=on-failure`;
- разумная задержка рестарта;
- остановка дочерних процессов;
- запись логов в journald;
- отсутствие секретов прямо в unit-файле.

В `README.md` добавь команды:

```bash
sudo systemctl daemon-reload
sudo systemctl enable italian-tutor
sudo systemctl start italian-tutor
sudo systemctl status italian-tutor
journalctl -u italian-tutor -f
```

Не выполняй команды с `sudo` автоматически без явного разрешения пользователя.

## 6.3. Обновление

`update.sh` должен:

- не удалять пользовательскую базу;
- при наличии Git безопасно получать обновления только после проверки рабочего дерева;
- устанавливать зависимости;
- выполнять миграции;
- создавать production build;
- перезапускать сервис только при успешной сборке;
- сообщать об ошибке без потери текущих данных.

## 6.4. Резервное копирование

`backup.sh` должен:

- создавать директорию резервных копий;
- корректно копировать SQLite-базу;
- использовать безопасный способ резервирования работающей базы;
- добавлять дату и время в имя файла;
- не включать `.env` и secrets в backup по умолчанию;
- сохранять пользовательский прогресс, словарь и настройки.

`restore.sh` должен:

- проверять существование файла;
- делать резервную копию текущей базы перед восстановлением;
- просить явное подтверждение;
- останавливать сервис перед заменой базы;
- возвращать понятный результат;
- не принимать произвольные небезопасные пути без проверки.

## 6.5. Удаление

`uninstall.sh` должен:

- не удалять пользовательские данные без отдельного подтверждения;
- позволять удалить только сервис и приложение;
- отдельно спрашивать, нужно ли удалять базу и backups.

# 7. Переменные окружения

Создай `.env.example`.

Минимальные переменные:

```env
NODE_ENV=development
HOST=127.0.0.1
PORT=3000
DATA_DIR=./data
DATABASE_PATH=./data/italian-tutor.sqlite

ENABLE_LIVE_AI=false
OPENAI_API_KEY=
```

Правила:

- приложение работает без `OPENAI_API_KEY`;
- `.env` добавлен в `.gitignore`;
- реальный ключ не попадает в репозиторий;
- ключ не отправляется в frontend;
- ключ не отображается в интерфейсе;
- ключ не записывается в логи;
- `ENABLE_LIVE_AI=false` принудительно включает локальный режим;
- при ошибке live AI приложение переключается на demo AI;
- пользователь получает понятное сообщение, а не stack trace.

# 12. Пользователь и локальные данные

Регистрация не обязательна.

При первом запуске:

1. Создай анонимный профиль.
2. Сгенерируй `anonymousId`.
3. Сохрани идентификатор в localStorage.
4. Свяжи его с локальной записью в SQLite.
5. Не собирай лишние персональные данные.

В SQLite сохраняй:

- профиль;
- результаты onboarding;
- прогресс уроков;
- пользовательские слова;
- интервалы повторения;
- попытки выполнения;
- результаты аудирования;
- метаданные произношения;
- достижения;
- состояние AI-диалогов.

Не сохраняй:

- аудиофайлы;
- Blob;
- WAV;
- MP3;
- MediaStream;
- необработанные аудиоданные;
- API-ключи.

Если backend временно недоступен:

- приложение не должно терять текущий экран;
- используй localStorage как временный fallback;
- покажи метку «Локальный демо-режим»;
- после восстановления сервера синхронизируй данные без дублирования.
