# Аудит учебного интерфейса и архитектуры

## Изменения

- Каталог выделен в CourseOverview: следующий незавершённый урок, реальный прогресс, доступные подписи статусов, адаптивный интерфейс.
- Добавлен единый слой оформления учебных страниц: компактная типографика, видимые этапы, выбранные ответы, мобильная навигация и ссылка пропуска меню.
- Контент курса кешируется на пять минут; учебные результаты продолжают обновляться после записи.
- Сессия урока пересоздаётся при смене параметров маршрута. Повторение завершённого урока начинается с первой карточки.
- Распознавание и озвучивание останавливаются при уходе из урока; смена этапа запрещена во время записи результата.
- Исправлены двойное начисление последнего ответа, несбрасываемая сумма и повторяющиеся варианты аудирования.
- В учебном интерфейсе успешное завершение проверки требует 80% правильных ответов.

## Открытые архитектурные проблемы

1. Сервер принимает completed и completionPercent от клиента. Порог интерфейса не является серверной гарантией знаний. Нужна серверная сессия экзамена с уникальными вопросами, идемпотентной записью ответов и вычислением результата в транзакции.
2. Listening, pronunciation и quiz отправляют word-N, поэтому сервер учитывает их как vocabulary. Требуются типизированные упражнения и отдельная статистика навыков. Проверка распознанного текста не является оценкой фонетики.
3. Большой App.tsx содержит legacy-компоненты и инициализирует anonymous ID. Нужен отдельный entrypoint совместимости, удаление старых учебных маршрутов из интернет-версии и lazy loading разделов.
4. Активная программа берётся из первого enrollment. Нужна явная настройка текущей программы пользователя.
5. GET словаря, интервальное повторение и мини-экзамен для открытия третьего блока пока не перенесены полностью.
6. PostgreSQL интеграционные тесты пропускаются без TEST_DATABASE_URL. Проверка HTTP 200 и наличие строк в bundle не заменяют браузерный сценарий входа, прохождения урока и повторного открытия прогресса.

## Приоритет следующего этапа

Серверная проверка знаний и идемпотентность → отдельный интернет-entrypoint → словарь и повторение → единая настройка активного курса → браузерная приёмка с PostgreSQL. Исходные учебные результаты не пересчитывать без отдельного плана миграции.

## Проверка этого изменения

- `npm run check`: успешно; typecheck, 51 тест и production-сборка прошли. 26 PostgreSQL-тестов пропущены без тестовой БД.
- Добавлен регрессионный сценарий: один правильный ответ из пяти даёт 100/500, не завершает урок, повторная попытка сбрасывает счёт.
- Действующий production `/api/health`: HTTP 200, база доступна. Это проверка существующего развёртывания, не новых изменений.
- Браузерная визуальная приёмка и проверка реального микрофона не выполнены. Изменения на VPS не опубликованы.
