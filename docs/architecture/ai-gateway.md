# AI Gateway и учёт использования

Интернет-контур использует только `POST /api/v1/tutor`. Идентификаторы пользователя и семьи выводятся из серверной сессии; тело запроса является strict-схемой и не принимает `userId`, `familyId` или `anonymousId`. Совместимый SQLite endpoint `/api/tutor` временно сохранён для локального клиента.

Gateway выбирает зарегистрированную модель, резервирует верхнюю оценку токенов атомарной `SECURITY DEFINER`-функцией, вызывает провайдера и закрывает резерв фактическим usage. Лимиты пользователя и семьи проверяются под advisory lock, поэтому параллельные запросы не могут независимо потратить один остаток. Runtime-роль остаётся `NOBYPASSRLS` и имеет только `EXECUTE` на узкие бухгалтерские функции.

`ai.requests` и `ai.usage_ledger` намеренно не имеют колонок prompt/response. Они содержат только пользователя, семейный snapshot, модель, безопасный код результата, latency, токены и стоимость по зафиксированной версии цены. API-ключи читаются только из server environment; в каталоге хранится лишь имя переменной секрета.

Demo Provider не требует ключей и выбирается, когда `ENABLE_LIVE_AI=false` или ключ OpenRouter отсутствует. Внешний провайдер ограничен таймаутом и общей параллельностью. Повтор выполняется один раз только для 429/5xx/timeout; после последовательных сбоев открывается circuit breaker. Ошибка внешнего провайдера освобождает резерв и возвращает безопасный demo fallback.

Для live-режима семейный администратор должен включить `aiEnabled`, разрешить `AI_MODEL_KEY` и задать месячный лимит. Модель, провайдер и версия цены должны существовать в каталоге. Изменение цены создаёт новую версию; прошлые ledger-записи не пересчитываются.
