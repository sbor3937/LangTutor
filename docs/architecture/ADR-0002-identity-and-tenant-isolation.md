# ADR-0002: identity и tenant isolation

- Статус: принят
- Дата: 2026-08-23

## Решение

Аккаунт пользователя отделяется от членства в семье. Учебные данные принадлежат `user_id`; семейные настройки, секреты и бюджеты принадлежат `family_id`. Пользователь может иметь не более одного активного членства.

Полномочия устанавливаются только из проверенной серверной сессии. Каждый tenant-запрос выполняется в транзакции с `SET LOCAL app.user_id` и `SET LOCAL app.family_id`. Runtime-role не владеет таблицами и не имеет `BYPASSRLS`; критические таблицы используют `FORCE ROW LEVEL SECURITY`.

## Защита в глубину

Application services проверяют capabilities. RLS остаётся независимым вторым барьером. `user_id` и `family_id` из body, query или route не предоставляют полномочия. Миграции запускает отдельная role. Фоновые задания повторно устанавливают проверенный контекст.

## Проверка

Integration tests выполняются реальной runtime-role и доказывают невозможность cross-user/cross-family чтения и записи, включая попытки подмены входных идентификаторов.
